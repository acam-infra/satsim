# 用受控场景验证两条核心结论（C1 重调度收益与 C2 带宽争用代价）

我们将仿真收敛为“YAML 声明式配置 + 单一 SimPy 事件循环”，专门用来清晰地分开验证两条核心结论：
1. **结论 C1（重调度收益）**：当卫星发生限功切换（亮暗切换、算力降频）时，只做**首次分配**无法应对算力变化，必须靠运行中途的**无消耗迁移**把请求挪到算力充足的卫星上才能保住吞吐。
2. **结论 C2（带宽争用代价）**：当迁移必须通过星间链路传输状态（**占带宽迁移**）时，多条迁移流会与背景流量争抢有限的链路带宽，导致随机迁移变慢甚至超时中断，吞吐大幅回落。

所有可调参数与调度策略都通过白名单校验，配套的场景背景说明（`scene_*.yaml`）严格对应已生效的配置项。请求是否达标只检查限功切换之后的生成速度（TPOT）。我们没有直接照搬笨重的全星座引擎（如 `satellite-llm-scheduling`），也没有退化成不含时间过程的静态代数快照——前者包袱太重，后者无法模拟多条流在星间链路上的动态抢带宽过程。
