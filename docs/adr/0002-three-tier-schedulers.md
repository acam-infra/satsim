# 调度策略统一为论文三档（首次分配 / 无消耗迁移 / 占带宽迁移）

我们将原本拆散的“初次放置（placement）+ 重调度（rebalance）”两个并列配置项，合并为与论文叙事完全对齐的三档全局调度策略：
1. **首次分配（`place_once`）**：请求到达时放一次，后续绝不迁移；
2. **无消耗迁移（`rebalance_free`）**：按负载启发式迁移，且假设迁移瞬间完成、不占星间链路带宽（理想上界）；
3. **占带宽迁移**：迁移必须走星间链路传输数据（其中简单基线 **随机迁移 `rebalance_random`** 已实现，**自研策略 `rebalance_ours`** 仅保留占位待实现）。

每个调度器（`Scheduler`）同时负责初次放置和运行中途迁移，迁移是否占用星间带宽则由独立的链路开销模型（`link_cost`）控制。这样实验配置与论文里的三档对比完全一一对应，避免读者误以为初次放置和重调度是可以随意混搭的两套独立插件。
