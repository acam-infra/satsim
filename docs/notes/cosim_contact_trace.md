# 协同仿真实验：轨道时变拓扑下的在轨推理调度

引擎架构见 `docs/adr/0005-cosim-contact-trace.md`，复现与回放说明在文末。

## 核心问题

前期 orbitsim 纯几何分析（`research_out/README.md`）提出两个假设：
1. **地影可预知**：卫星进出地影的时刻完全由轨道决定，靠星历在首次放置时就能避开暗星；
2. **接触窗口短**：遥感星（RS）到算力星的单条激光链路接触只有分钟级，这可能是迫使请求在运行中迁移的主要原因。

但纯几何分析没有真正跑过请求流。本实验把 orbitsim 导出的接触与地影轨迹接入 satsim 的流体网络与推理耗时模型，回答一个直接问题：**在真实的轨道时变拓扑上，运行中迁移到底比"只靠星历做首次放置"多赚多少达标率？**

## 实验场景

两个场景均包含 3 颗遥感星（RS-1030 / RS-1330 / RS-SAR），春分日，时长 2 小时，5 s 采样。每颗 RS 按泊松过程提交请求，其中 35% 为长任务（6k–18k token，需先上传 500 MB 图块）；长任务截止时间设为 `到达时刻 + 2 × 亮星独占解码耗时`。

| 场景 | 算力星座 | 链路规则 | 2 小时轨迹统计 |
|---|---|---|---|
| `cosim_coop_w53_v1` | Walker 53° 4×10，550 km | 面内环常连；跨面 +Grid ≤ 5000 km 在线；RS 单激光终端，保持当前算力星直到超出 4000 km | 跨面接触中位 17 min；RS 接触中位 4.7 min，每星每小时切换 11.8 次；算力星 32% 时间在地影 |
| `cosim_coop_sso2_v1` | SOW S-SSO2：4 簇 × 4 星，LTAN 10:30 / 13:30 | 簇内固定常连；簇间 ≤ 5000 km（实测从不达到） | RS 接触中位 5.1 min，每星每小时接触 1 次；算力星 36% 时间在地影 |

## 实验结果（3 种子均值）

### 场景一：Walker 53° 4×10（每颗 RS 45 请求/分钟，共约 12k 请求）

| 策略 | 长任务达标 | 全部达标 | 影内解码占比 | 迁移次数 | 迁移中止 |
|---|---|---|---|---|---|
| `greedy` | 95.9% | 98.4% | 2.4% | 0 | 0 |
| `reactive` | 97.1% | 98.8% | 0.2% | 232 | 0 |
| `ephemeris` | 99.3% | 99.7% | 1.8% | 0 | 0 |
| `contact_aware` | 99.9% | 100.0% | 1.6% | 304 | 0 |

### 场景二：S-SSO2 4×4（每颗 RS 4 请求/分钟）

| 策略 | 长任务达标 | 长任务交付 p90 | 影内解码占比 | 迁移次数 |
|---|---|---|---|---|
| `greedy` | 69.3% | 33 min | 28.5% | 0 |
| `reactive` | 69.1% | 33 min | 28.3% | 4 |
| `ephemeris` | 70.7% | 34 min | 28.1% | 0 |
| `contact_aware` | 69.4% | 33 min | 28.0% | 90 |

## 五条结论

1. **有星间网格时，接入切换被多跳中继吸收了。**
   Walker 场景里 RS 每小时换 12 次接入星，但只要连上任意一颗算力星，就能经面内环和跨面链路转发到全网 40 颗星。结果回传几乎不用等（deliver gap 接近 0），迁移中止 0 次。因此"单链路接触 7–8 min 就会迫使迁移"在带 ISL 网格的星座里不成立，论文表述需要修正。

2. **性能差距主要来自地影，而且约 85% 靠首次放置就能拿到。**
   从 `greedy` 到 `ephemeris`，长任务达标率从 95.9% 升至 99.3%（+3.4 个百分点）；加上运行中迁移（`contact_aware`）再升至 99.9%（+0.6 个百分点）。总计 4.0 个点的提升中，约 85% 来自星历放置，运行中迁移贡献约 15%，验证了几何分析的判断。

3. **"进影才搬"的反应式迁移不如不迁移的星历放置。**
   `reactive` 把影内解码压到了 0.2%，但长任务达标率只有 97.1%，低于 `ephemeris` 的 99.3%。原因是它先把请求放到快进影的卫星上，进影后再花时间搬走，且目标星选择不看未来星历。这张表直接回答了"为什么不能等进地影再搬"。

4. **簇间不连通时，交付卡在下一次过境，调度救不了。**
   S-SSO2 的 4 个算力簇彼此从不进入 5000 km，RS 每小时只能碰到一次算力簇。长任务交付 p90 高达 33 min，约 30% 请求超时；四种策略差距不到 2 个百分点。因为同簇 4 星几乎同时进地影（首尾时差 ≤ 100 s），簇内没有亮星可迁。这类构型的瓶颈在拓扑设计，不在调度算法。

5. **10 Gbps 星间链路下，带宽不是瓶颈。**
   1.6 GB 的 KV 状态在 10 Gbps 链路上只需 1–2 s，远短于分钟级的接触窗口和地影时长。要让带宽争用（C2）成为显著瓶颈，需要把链路带宽压到 0.1–0.5 Gbps 量级，或叠加遥感数传背景流。

## 灵敏度分析（Walker，单种子长任务达标率）

| 变量设置 | `greedy` | `ephemeris` | `contact_aware` |
|---|---|---|---|
| 截止 3×，6 请求/分钟 | 99.4% | 100% | 100% |
| 截止 2×，45 请求/分钟 | 96.1% | 99.4% | 99.9% |
| 截止 1.5×，45 请求/分钟 | 86.6% | 83.9% | 84.6% |
| `stream` 交付（解码中不允许断联），45/分钟 | 91.4% | 95.2% | 95.6% |

当截止时间收紧到 1.5× 时，排队等待成为主导因素。当前 `ephemeris` 只优化新请求自身的预计交付时间，没算它插入队列后把同节点已有请求拖慢的外部性，结果反而输给 `greedy`。这是下一版调度器要补齐的代价项。

## 对论文叙事的启示

- **不要把迁移动机写成"接触窗口短"**：有 ISL 网格时接入切换被中继吸收，没有网格时迁移也无处可去。
- **立得住的三条主线**：
  1. `ephemeris`（星历放置）是必须列入对比表的强基线；
  2. 运行中迁移在常规条件下带来 0.5–1 个百分点的增量，需要靠更紧的截止时间、更长的多轮会话或不可预知的功率波动来放大；
  3. 拓扑连通性对交付时延的影响远大于调度策略（S-SSO2 p90 33 min vs Walker 5.5 min）。

## 当前局限

- 地影简化为固定限功（80 W / 0.35×），未建电池充放电与热模型；
- 未计入 prefill 算力开销与激光链路重捕获时间；
- 遥感星仅作端点、不参与中继；
- 轨迹仅覆盖春分单日 2 小时；策略阈值（margin 20 s / 10%）尚未调优。

## 怎么看回放

协同仿真结果可以在 orbitsim 的 3-D 回放页 `http://localhost:5288/play.html` 中直接观看（见 `../orbitsim/viz/README.md`）：

- **切场景与策略**：左上角下拉框切换 `cosim_coop_w53_v1`（网格连通）与 `cosim_coop_sso2_v1`（簇间断联）；按数字键 `1`–`4` 或直接点击策略对比表的行切换四种策略。
- **看迁移与断链**：地球上默认只画橙色 KV 迁移箭头（带移动圆点）和红色断链/中止标记；需要看高频的请求上传/结果回传时，勾选"显示上传/回传"。
- **快速定位**：点"跳到下一次迁移"按钮直接跳到下一条 KV 迁移发生时刻；用 `Space` 暂停/播放，`←` / `→` 前后跳 60 秒。

## 复现命令

```bash
# 1. orbitsim：重新生成接触轨迹（可选，input/traces/ 已含导出文件）
cd ../orbitsim && uv run python export_cosim.py && cp cosim_out/*.json ../satsim/input/traces/

# 2. satsim：运行协同仿真并导出前端回放 JSON
uv run satsim-cosim configs/cosim_coop_w53_v1.yaml --viz ../orbitsim/viz/public/playback
uv run satsim-cosim configs/cosim_coop_sso2_v1.yaml --viz ../orbitsim/viz/public/playback

# 3. 灵敏度扫描
uv run python scripts/cosim_sweep.py configs/cosim_coop_w53_v1.yaml slo.deadline_factor_long 1.5 2 3 --seeds 1

# 4. 启动 3-D 回放页面
cd ../orbitsim/viz && npm run dev   # 打开 http://localhost:5288/play.html
```
