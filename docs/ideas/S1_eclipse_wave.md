## 一句话假设

把「定时限功」换成「阴影沿轨道依次扫过各星」，C1 照样成立；而且因为变暗的星是挨着的，迁移流量会同时挤向亮的一侧，随机迁移和贪心迁移的 C2 损失比主场景更大。

## 机制

物理背景：同一轨道面上的星，进出地影的时刻按轨道相位依次错开。低轨一圈约 95 分钟，其中约 35 分钟在阴影里。卫星进阴影后只能靠电池，功耗上限降低，时钟变慢。

仿真里的做法：给 `t_swap` 加一种新的 `anchor: eclipse_wave`，按下面的规则生成 `thermal.explicit_events`：

```yaml
t_swap:
  anchor: eclipse_wave
  start_s: 40        # 第一颗星进阴影的时刻（相对最大请求簇）
  stagger_s: 60      # 相邻两星进阴影的时间差，对应轨道相位差
  duration_s: 150    # 每颗星在阴影里待多久
  order: [0, 1, 2, 3]
  P_cap: 80
```

第 `k` 颗星的限功区间是 `[start + k·stagger, start + k·stagger + duration]`。参数要保证任意时刻都有星亮着、也有星暗着，并且暗区按环的方向移动。

时间是压缩过的（请求流本来就压进了 60 秒左右的簇），只保留「依次变暗、可预测、相邻」三个性质，不追求真实时长比例。

## 要多统计的指标

- **每条边每个方向的峰值并发迁移流**：看热点是不是出现在朝亮侧的那几条边上。
- **白搬次数**：迁移完成后 X 秒内目的地也变暗的次数。用来说明「目的地会过期」。

这两个指标只在本分支加，合入时再决定是否进主统计。

## 实验设计

- 场景：四星环，地影波参数扫 `stagger_s ∈ {30, 60, 120}`
- 对照组：首次分配、无消耗迁移、随机迁移，`B1` 有了就加上
- 种子：1–5

## 成功判据

1. C1 成立：无消耗迁移相对首次分配，有效吞吐提升 30% 以上。
2. 热点出现：朝亮侧那几条边的峰值并发流，明显高于背向亮侧的边。
3. C2 放大：随机迁移相对无消耗迁移的回落，比主场景的约 24% 更大。

## 放弃判据

- 四星环上热点不明显：改用 8 星环（`nodes: 8`）再试一次，还不明显就放弃本场景。
- C1 不成立：说明阴影期间场上没有足够的亮星可以迁入，回头调 `duration_s` 和 `stagger_s` 的比例。
