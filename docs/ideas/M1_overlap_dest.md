## 一句话假设

同样是迁去更快的星，挑路径上叠流最少的那颗，能让迁移按时传完的比例变高，超时中断变少，有效吞吐高于贪心加准入。

## 机制

每个控制周期，对变慢的源星上的请求：

1. **候选目的地**：时钟倍率比源星高、显存放得下的星。
2. **给每个候选估传输时间 `T`**：沿用 `B1` 的瓶颈速率估算。路径上每多一条已有迁移流，分到的带宽就少一份，所以重叠越多 `T` 越大。
3. **算收益**：

   ```text
   收益 = 剩余输出 token × (源星每 token 耗时 − 目的星每 token 耗时) − 传输期间少生成的 token
   ```

   `T` 超过超时线的直接剔除。
4. **选请求**：同一个源星上有多个请求时，按「收益 / KV 字节数」排序，先迁性价比高的：KV 小、剩余输出长。
5. **一个周期内连续发多条迁移时**，每发一条就更新路径占用，后面的候选会看到前面那条。

和传统流量工程的区别：不解全网多商品流，只在几个候选里比，因为星少、每个周期要快速决定。

- 对照组：首次分配、无消耗迁移、随机迁移、贪心加准入（`B1`）
- 种子：1–5

## 成功判据

在跨轨网格或 E★ 上，有效吞吐比贪心加准入高一个标准差以上，同时超时中断不多于它。四星环上至少不比它差。

## 放弃判据

四星环上任意两颗星之间只有两条路，选择空间小。如果跨轨网格和 E★ 上也和贪心加准入没有差别，说明「挑目的地」这一维不够，并入 `M2` 或 `M4`，不再单独推进。
