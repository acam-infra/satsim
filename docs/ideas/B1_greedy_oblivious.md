## 一句话假设

随机迁移太弱，赢过它说明不了问题。一个「挑最快目的地、不管链路」的贪心策略，加上「传不完就不发」的准入，可能已经补回大部分差距。必须先知道它的成绩，才知道剩给 `M*` 的空间有多大。

## 机制

两个调度器，都只在源星已经变慢时才动：

**`rebalance_greedy`（贪心）**

- 选请求：在最慢的那颗星上，挑剩余输出 token 最多的请求，收益最大。
- 选目的地：在显存放得下的星里挑当前时钟倍率最高的，不看链路。
- 其他限制沿用随机迁移：每个请求最多迁一次，`MAX_INFLIGHT` / `MAX_OUT` 不变。

**`rebalance_greedy_admit`（贪心加准入）**

在贪心基础上，发起迁移前估一下传输时间：

```text
预计传输时间 = KV 字节数 / 路径瓶颈上的预计速率 + 跳数 × 每跳时延
路径瓶颈上的预计速率 = min over 路径上每条边 ( (链路容量 − 高优先级背景流) / (已有迁移流数 + 1) )
```

预计传输时间超过 `cost.timeout_s` 的一定比例（先取 0.8）就不发。

这里只做准入，不挑路径、不挑时机。挑路径属于 `M1`，挑时机属于 `M2`。

## 判读规则

这条是基线，没有「成功」一说，只看它把差距吃掉多少。记 `G` = 无消耗迁移有效吞吐 − 贪心加准入有效吞吐：

- `G` 大于无消耗迁移的 15%：`M*` 空间充足，按原计划推进。
- `G` 在 5% 到 15% 之间：`M*` 只在主场景上难赢，重心转到 `S1` 地影波和 E★ 这类争用更重的场景。
- `G` 小于 5%：主场景上「看链路」没有意义，故事必须靠 `S1` 撑住，否则要重想贡献。
