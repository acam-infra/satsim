# 并行思路看板

自研迁移（`rebalance_ours`）还没有定型，几条思路并行推进。本目录每条思路一个文件，互不依赖，分别 review、分别看效果。整体故事线见 `docs/notes/research_approach.md`，相关工作见 `docs/notes/related_work_migration_traffic.md`。

## 分类

| 类别 | 前缀 | 回答的问题 | 改动范围 |
|---|---|---|---|
| 场景 | `S` | 算力怎么变，问题才成立、才像真的 | 只改环境（`base_*` / `t_swap` / 温控），不改调度器 |
| 基线 | `B` | 自研策略至少要赢过谁 | 新增调度器，不碰别的思路 |
| 方法 | `M` | 自研策略具体怎么做 | 新增调度器，可以复用 `B` 的工具函数 |

`S` 决定在哪个环境里比，`M` 决定拿什么比。两类可以交叉组合：任意 `M` 都应该在主场景和至少一个 `S` 场景上各跑一遍。

## 状态看板

状态取值：`草案` → `进行中` → `有结果` → `已合入` / `放弃`。

| 编号 | 思路 | 类别 | 状态 | 一句话 |
|---|---|---|---|---|
| [S1](S1_eclipse_wave.md) | 地影波 | 场景 | 草案 | 阴影沿轨道依次扫过，变暗可预测，迁移流量朝同一方向挤 |
| [S2](S2_thermal_asymmetry.md) | 温控加空间不对称 | 场景 | 草案 | 动态温控下人为制造冷热差，让 C1 在温控故事里也成立 |
| [B1](B1_greedy_oblivious.md) | 贪心不看链路 | 基线 | 草案 | 挑最快的目的地，不管链路；外加「传不完就不发」的准入 |
| [M1](M1_overlap_dest.md) | 路径重叠选目的地 | 方法（空间） | 草案 | 目的地在更快的星里挑路径上叠流最少的 |
| [M2](M2_staggered_premigrate.md) | 提前迁、错峰迁 | 方法（时间） | 草案 | 利用可预测的变暗时刻，把迁移在时间上摊开 |
| [M3](M3_transfer_vs_recompute.md) | 传 KV、重算还是留下 | 方法（迁移方式） | 草案 | 每次迁移在三种方式里按预计完成时间选 |
| [M4](M4_deadline_admission.md) | 截止感知的准入与排序 | 方法（带宽） | 草案 | 把一次迁移当一组流，按超时线决定发不发、谁先传 |

## 隔离规则

目的：一条思路失败或推翻，不影响其他思路，也不污染主表。

1. **文档**：每条思路只写自己的 `docs/ideas/<编号>_<slug>.md`，按 [`_template.md`](_template.md) 填。结果写在自己文件里，不写 `README.md` 主表。
2. **分支**：每条思路一个分支 `idea/<编号>-<slug>`，建议用独立 worktree，避免来回切换：

   ```bash
   git worktree add ../satsim-M1 -b idea/M1-overlap-dest
   ```

3. **调度器**：每条思路新建自己的文件 `src/satsim/method/policies/schedulers/rebalance_<slug>.py`，`scheduler` 取值为 `rebalance_<slug>`。共享改动只允许在 `registry.py` 的 `_scheduler()` 里加一个分支。不要改 `rebalance_ours.py`，它留给最终胜出的方案。
4. **环境**：`S` 类改环境时新建 `base_*` 或新的 `t_swap.anchor`，不改现有 `base_ring_s1.yaml`，保证主实验数字不变。
5. **实验配置**：每条思路自己的 `exp_*` 文件，名字带编号，比如 `exp_ring_s1_M1_overlap_v1.yaml`。输出自动落在 `runs/<name>/`，不会互相覆盖。
6. **公共工具**：两条以上思路都要用的函数（比如估算路径剩余带宽），先在各自分支里写；确认要合入时再抽到 `_select.py` 或新的 `_net.py`。

## 统一对比口径

所有思路的结果表都要可比：

- **主场景**：`exp_ring_s1_cost_claims_v3`，种子 1–5。`S` 类另报自己的场景。
- **固定对照组**：首次分配、无消耗迁移、随机迁移三档必须同表出现。`B1` 有结果之后，`M*` 还要带上 `B1`。
- **表格规范**：遵守根目录 `AGENTS.md` 的结果表规范：以首次分配为 100%，百分比写在数值旁，粗体标最优，列名标 ↑ / ↓。
- **必报列**：达标长请求 ↑、有效吞吐 ↑、迁移流量 ↓、超时中断 ↓。可以按需加列，比如瓶颈边峰值并发流。
- **种子波动**：5 个种子的标准差写在表下一行，差距小于一个标准差的不算赢。

## 合入流程

某条思路达到自己写的成功判据后：

1. 在思路文件里把状态改成 `有结果`，贴结果表。
2. 发 PR，review 只看这条思路的文件和调度器。
3. 决定采纳后，把实现搬进 `rebalance_ours.py`，更新 `README.md` 主表，状态改成 `已合入`。
4. 放弃的思路保留文件，状态改成 `放弃`，写清楚为什么放弃，免得以后重复尝试。
